# LostSocks

Пародийный видеохостинг про носки: сетка превью, категории, плеер, лайки, комментарии.
Контент заливается через админку, демо-каталога нет — пока ничего не залито, лента пустая.
Обложки не рисуются и не загружаются отдельно: сервер режет случайный кадр из самого ролика.

## Что внутри

```
backend/
  server.js        Express: роуты /api/*, раздача фронта
  data.js          справочник категорий и названий цветов
  store.js         залитые ролики: метаданные в uploads/socks.json
  profiles.js      профили гостей: ник, описание, аватарка
  video.js         ffprobe/ffmpeg: длительность и кадр для превью
  uploads/         сюда ложатся ролики, превью и аватарки (в git не попадает)
  package.json
frontend/
  index.html
  styles.css
  app.js           состояние, запросы к API, плеер
  socks.js         рисованные носки — нужны только аватаркам профилей
```

Бэкенд — Node 20+, Express 5 и multer для приёма файлов; кадры режет системный ffmpeg.
Фронт без сборки: три файла, никаких фреймворков и npm.

## Запуск

```bash
cd backend
npm install
npm start          # или npm run dev — с автоперезапуском по правкам
```

`npm start` читает `.env` из корня проекта — туда кладётся `ADMIN_PASSWORD`
(образец: `.env.example`).

Сайт — на http://127.0.0.1:8000. Порт меняется переменной `PORT`.

Фронт можно открыть и отдельным файлом (`frontend/index.html`) — тогда он сам стучится
на `http://127.0.0.1:8000/api`, CORS для этого уже открыт.

## API

| Метод | Путь | Зачем |
|---|---|---|
| GET | `/api/categories` | список категорий для чипсов |
| GET | `/api/socks` | лента; `cat`, `q`, `sort` (new/views/likes/dur), `offset`, `limit` |
| GET | `/api/socks/:id` | один ролик; заодно считает просмотр (`?count=false` — не считать) |
| POST | `/api/socks/:id/like` | `?liked=true\|false` |
| GET | `/api/socks/:id/comments` | ветка комментариев |
| POST | `/api/socks/:id/comments` | `{"text": "..."}`, до 160 символов |
| POST | `/api/admin/login` | `{"password": "…"}` → токен админа |
| POST | `/api/admin/logout` | погасить свой токен |
| GET | `/api/admin/me` | признал ли сервер этот токен |
| GET | `/api/admin/socks` | все ролики для панели |
| POST | `/api/socks` | загрузка ролика, `multipart/form-data` (админ) |
| PATCH | `/api/socks/:id` | правка `title`, `desc`, `cats`, `tags` (админ) |
| POST | `/api/socks/:id/reshoot` | вырезать другой случайный кадр (админ) |
| DELETE | `/api/socks/:id` | удалить ролик вместе с файлами (админ) |
| GET | `/api/me` | свой профиль; первый заход заводит гостя и выдаёт токен |
| PATCH | `/api/me` | `{"nick": "…", "bio": "…", "pal": 0-9}` |
| POST | `/api/me/avatar` | форма с полем `avatar`: jpg, png, webp, gif до 5 МБ |
| DELETE | `/api/me/avatar` | снять картинку, вернуть рисованный носок |
| GET | `/api/profiles/:id` | чужой профиль вместе с его носками |

Ошибки приходят как `{"detail": "..."}` — фронт показывает это поле как есть.

## Профили

Регистрации нет, профиль нужен только для комментариев. На первый заход `GET /api/me`
заводит гостя и отдаёт токен, фронт кладёт
его в `localStorage` и потом шлёт заголовком `X-Sock-Token`. По токену находится профиль:
ник, описание, аватарка. Без аватарки рисуется носок — цвет выбирается в самом профиле.

Комментарии подписываются профилем, а ник и картинка подставляются при выдаче — поэтому
после смены ника старые комментарии переподписываются сами. Ролик помнит, из-под какого
профиля его залили, но право удалять и переснимать даёт не профиль, а вход в админку.

Токен — это весь пароль. Кто угодно с этой строкой войдёт в профиль, так что ничего
ценного там держать не стоит. Для шутки про носки сойдёт, для чего-то большего нужна
нормальная авторизация.

Профили и аватарки лежат в `backend/uploads/` (`profiles.json` и `avatar/`) и рестарт
переживают — в отличие от лайков и комментариев.

## Админка

Кнопка «Админка» в шапке. Пароль берётся из `ADMIN_PASSWORD`:

```bash
ADMIN_PASSWORD=свой-пароль npm start
```

Переменной нет — сервер придумает разовый пароль и напечатает его в консоли при запуске,
так что заливать ролики без пароля не выйдет. После входа сервер выдаёт токен, фронт
держит его в `localStorage` и шлёт заголовком `X-Admin-Token`. Токены живут в памяти:
перезапустил сервер — надо войти заново.

В панели: форма загрузки и список всех роликов, у каждого — «Изменить», «Другой кадр»
и «Удалить». «Изменить» раскрывает форму прямо под строкой: название, описание, категории
и теги. Теги пишутся через запятую, решётку подставляет сервер, регистр приводится к нижнему,
повторы выбрасываются — не больше восьми штук по 24 символа. Правки сразу видны и в ленте,
и в открытом плеере. «Другой кадр» и «Удалить» есть и в самом плеере, когда вход выполнен.

Поля формы — `video` (файл), `title`, `desc` и `cats` (повторяется для каждой категории).

Что делает сервер, приняв файл:

1. кладёт его в `backend/uploads/video/` под сгенерированным именем;
2. спрашивает у `ffprobe` длительность — если её нет, файл не видео, и он удаляется;
3. выбирает случайную секунду между 10% и 85% ролика (края пропускает: там обычно
   чернота или титры) и вырезает оттуда кадр в `uploads/thumb/` через `ffmpeg`;
4. записывает метаданные в `uploads/socks.json`.

Этот кадр и становится обложкой в ленте. Если попался неудачный, кнопка «Другой кадр»
перережет превью заново. При наведении на карточку превью оживает: ролик
догружается только в этот момент и стартует с той же секунды, что и обложка.

Нужен **ffmpeg с ffprobe** в `PATH` — без них сервер поднимется, но загрузку отклонит
и предупредит об этом в консоли при старте.

Ограничения: один файл за раз, до 300 МБ (меняется переменной `MAX_UPLOAD_MB`),
расширения mp4, webm, mov, mkv, m4v, avi, ogv. Видео отдаётся с поддержкой Range,
поэтому перемотка в плеере работает.

## Оговорки

Лайки, комментарии и админские токены живут в памяти процесса: перезапустил сервер —
обнулились. Ролики, просмотры и профили лежат на диске и остаются.
Лайк один на всех: профиль подписывает комментарии, но не лайки.
Просмотр засчитывается на каждое открытие карточки, без всякой защиты от накрутки.
Если нужна БД, менять придётся `store.js` и `profiles.js`.

Админ всего один, и пароль у него общий. Для учебного проекта этого хватает, для чего-то
настоящего нужны отдельные учётки и https — сейчас пароль уходит на сервер как есть.

Сайт — шутка. Ни один носок не пострадал, кроме того белого, которого постирали с красным.
